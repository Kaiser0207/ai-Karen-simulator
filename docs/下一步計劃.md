## P0 ── 把 SER 接進遊戲(核心,優先)

> 目標:玩家錄音時,同一段音檔既轉文字(已有)、也判語氣情緒(新),
> 顯示在 UI 並可計入評審 / 即時提示。

**VRAM 評估**:推論時 whisper medium(~2.2GB)+ CRAB(XLS-R 300M + XLM-R large,推論 ~4-6GB)
合計 < 10GB,在 24GB 上同時載入安全(推論遠輕於訓練)。仍守「不准 OOM」。

1. **`services/ser.py` 推論封裝**
   - 載 `experiments/okeke_msp_4class` 的 audio/text LoRA adapter + SER 頭 + `train_norm_stat.pkl`。
   - 介面 `predict(wav_path) -> {label, probs}`;比照 STT 做背景 `warmup()`。
   - 文字模態:用 STT 轉出的文字餵 XLM-R(雙模態才是 CRAB 的設計)。
2. **API**:`/api/stt` 回傳加上 `emotion` 欄位(同一個 wav 一次處理),或新增 `/api/voice-emotion`。
3. **前端**:錄音送出後,文字框旁顯示偵測語氣(小圖示/標籤,如 😡 語氣偏衝)。
4. **硬映射用途**(挑一個先做):
   - (a) **即時提示**:玩家語氣 Angry → 浮出「你的語氣可能讓客人更火」。最直覺、demo 效果好。
   - (b) **計入評審**:把語氣納入 JudgeReport 的「情緒控制」維度。
   - (c) **影響奧客**:玩家語氣衝 → 奧客 anger delta 加成。最有玩法但要調平衡。

**建議**:先做 1→2→3→4(a),最小可 demo;(b)(c) 行有餘力再加。
