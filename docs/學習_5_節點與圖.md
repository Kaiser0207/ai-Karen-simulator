## 1. 節點是什麼?

一個節點 = 一個**純函式**:`讀 state → 做事 → 回傳要更新的欄位(dict)`。
LangGraph 會把回傳的 dict 合併進 state(`messages` 是追加,其他是覆蓋)。

---

## 2. 六個節點逐一拆解

### ① customer_brain —— 奧客大腦
```python
def customer_brain(state):
    turn = llm.customer_turn(state["system_prompt"], state["anger"],
                             state["messages"], state["player_input"])
    return {
        "ai_reply": turn.reply,
        "anger_change": turn.anger_change,
        "emotion": turn.emotion,
        "ended": turn.ended,
        "messages": [HumanMessage(state["player_input"]), AIMessage(turn.reply)],
    }
```
- **做什麼**:呼叫服務層(第 4 課)拿到 `CustomerTurn`,拆進 state。
- **注意**:這裡把「玩家這句 + 奧客這句」追加進 `messages`(這就是歷史累積的地方)。

### ② apply_state —— 套用憤怒變化
```python
def apply_state(state):
    delta = max(-30, min(30, state["anger_change"]))     # 夾限(防暴衝/防作弊)
    new_anger = max(0, min(100, state["anger"] + delta)) # 血條夾 0~100
    return {"anger": new_anger, "turn": state["turn"] + 1}
```
- **重點**:LLM 給的 anger_change 只是「建議」,**真正改血條由這裡控制**,並回合 +1。

### ③ classify_ending —— 判斷結局
```python
def classify_ending(state):
    if state["anger"] >= 100:        et = "fail"
    elif state["anger"] <= 0 or state["ended"]:  et = "success"
    elif state["turn"] >= state["max_turns"]:    et = "timeout"
    else:                            et = None
    return {"ending_type": et}
```
- **做什麼**:依優先序判斷結局類型,**寫進 state**。
- ⭐ **為什麼是獨立節點(踩過的雷)**:LangGraph 的「岔路判斷函式」回傳值**只能選邊、不會寫進 state**。如果在岔路直接決定結局,後面 `set_ending` 讀不到。所以拆成「節點寫 → 岔路讀」。

### ④ route_after_classify —— 岔路(這是邊,不是節點)
```python
def route_after_classify(state):
    return "continue" if state["ending_type"] is None else "ending"
```
- 只**讀** state 決定走哪條邊。

### ⑤ set_ending —— 收尾、播結局台詞
```python
def set_ending(state):
    line = state["scenario"]["ending_lines"][state["ending_type"]]
    return {"ended": True,
            "emotion": _ENDING_EMOTION.get(state["ending_type"], "neutral"),
            "messages": [AIMessage(line)]}
```
- **做什麼**:從 scenario 取**預寫好的結局台詞**(第 3 課)附加進對話,標記結束。

### ⑥ judge —— 評審大腦
```python
def judge(state):
    report = llm.judge_report(state["messages"])
    return {"report": report.model_dump()}
```
- **做什麼**:呼叫評審(第 4 課),把報告轉成 dict 存進 state(`model_dump()` 把 Pydantic 物件轉字典)。

## 3. build.py —— 把節點串成圖

```python
def build_graph(checkpointer):
    g = StateGraph(GameState)
    g.add_node("customer_brain", customer_brain)
    g.add_node("apply_state", apply_state)
    g.add_node("classify_ending", classify_ending)
    g.add_node("set_ending", set_ending)
    g.add_node("judge", judge)

    g.add_edge(START, "customer_brain")
    g.add_edge("customer_brain", "apply_state")
    g.add_edge("apply_state", "classify_ending")
    g.add_conditional_edges("classify_ending", route_after_classify, {
        "continue": END,           # 沒結束 → 結束本次 invoke,等下一句
        "ending":   "set_ending",  # 結束 → 播台詞 → 評審
    })
    g.add_edge("set_ending", "judge")
    g.add_edge("judge", END)
    return g.compile(checkpointer=checkpointer)
```

### 圖的形狀
```
START → customer_brain → apply_state → classify_ending ─┬─[continue]→ END
                                                        └─[ending]→ set_ending → judge → END
```

- 大部分是**固定邊**(做完 A 一定到 B)。
- 只有 `classify_ending` 後面是**條件邊**(岔路),由 `route_after_classify` 決定。
- `checkpointer` 參數就是記憶(第 6 課接)。

---

## 4. ⭐「一次 invoke = 一個回合」

注意:**沒結束就走到 END 了**。下一句玩家輸入會「**從 START 再跑一次整張圖**」,但因為 checkpointer 記得上次的 state,憤怒值和歷史都接得上。
所以「多回合」不是靠圖內部迴圈,而是靠「**外部一直 invoke + 記憶**」。

## 🎓 老師可能問

**Q:結局怎麼判定?**
A:`classify_ending` 節點依優先序檢查:憤怒≥100→失敗、憤怒≤0或LLM說和解→成功、回合用完→超時、否則繼續。結果寫進 state,再由條件邊決定走「繼續」或「收尾+評審」。

**Q:為什麼不把判定寫在岔路函式就好?**
A:因為 LangGraph 岔路函式的回傳值只用來選邊、不會寫進 state,後面 set_ending 需要從 state 讀結局類型才能取對應台詞。所以拆成「節點寫狀態 + 岔路讀狀態」。這是我實作時踩到的雷。

**Q:LLM 亂給很高的 anger_change 會怎樣?**
A:不會失控。`apply_state` 把它硬夾在 ±30,血條再夾 0~100。LLM 只能建議,後端決定實際變化。

**Q:遊戲怎麼進行多個回合?**
A:每次玩家輸入就 invoke 一次整張圖(=一回合),沒結束就到 END;靠 checkpointer 以 thread_id 保存 state,下次 invoke 自動接續憤怒值與歷史。
