## 1. 最重要的觀念:沒有「兩台伺服器」

很多人以為「前端連後端」一定要架 API(HTTP)。**你的專案不用。**

因為 **Gradio 也是 Python**,前端和後端**在同一個程式裡跑**(in-process)。所謂「前端呼叫後端」,其實就是:

> **import 後端的函式,然後直接呼叫它。**

```
            同一個 Python 程式
┌─────────────────────────────────────┐
│  Gradio 介面(按鈕、輸入框)          │
│        │ 直接呼叫(不是 HTTP)         │
│        ▼                              │
│  graph.invoke() / loader.load()  ←後端 │
└─────────────────────────────────────┘
```

對比:如果前端是 React / 手機 App(非 Python),才需要把後端包成 API 用 HTTP 連。**你用 Gradio,所以最單純。**

---

## 2. 前後端的「連接合約」其實只有 4 件事

整個 app.py 對後端的呼叫,就這幾個:

```python
loader.list_scenarios()      # ① 列出關卡 → 填下拉選單
loader.load(scenario_id)     # ② 開一場遊戲 → 拿到開局 state
GRAPH.invoke(payload, config)# ③ 跑一回合
result["anger"] / result["ai_reply"] / result["ended"] / result["report"]  # ④ 讀結果更新畫面
```

**前端做的事 = 收集輸入 → 呼叫上面這幾個 → 把回傳值畫到畫面。** 就這樣。

## 3. app.py 結構導覽

### (A) 啟動時:建一次圖

```python
_conn = sqlite3.connect("game_state.db", check_same_thread=False)
GRAPH = build_graph(SqliteSaver(_conn))
```
- **整個程式只建一次圖**,所有玩家共用(不是每回合重建)。
- `check_same_thread=False`:因為 **Gradio 用多執行緒處理請求**,SQLite 連線預設綁單一執行緒,要關掉這限制。

### (B) session 狀態:用 `gr.State` 存每位玩家的進度

```python
st_sid   = gr.State(None)    # 這場遊戲的 thread_id
st_init  = gr.State(None)    # 開局 state(第一回合要送整包)
st_first = gr.State(True)    # 是不是第一回合
st_done  = gr.State(False)   # 結束了沒
```
- `gr.State` 是 Gradio 幫**每個瀏覽器分頁**各自保存的變數。多人同時玩不會混在一起。

### (C) 兩個事件處理函式(handler)= 後端的入口

**`start_game(scenario_id)`** —— 按「開始挑戰」時:
```python
init = loader.load(scenario_id)     # 開局 state
sid = uuid.uuid4().hex              # 給這場一個身分證
chat = [{"role":"assistant","content": 開場白}]
return chat, anger_html(...), sid, init, True, False, ...
```

**`player_say(text, chat, sid, init, first, done)`** —— 送出一句話時:
```python
payload = {**init, "player_input": text} if first else {"player_input": text}
result = GRAPH.invoke(payload, {"configurable": {"thread_id": sid}})  # ← 呼叫後端!
chat += [{"role":"user","content":text}, {"role":"assistant","content":result["ai_reply"]}]
anger = result["anger"]
if result["ended"]: ... 出報告、鎖輸入
```

### (D) 事件綁定 = 真正的「前端連後端」

```python
start_btn.click(start_game, inputs=[scenario_dd], outputs=[chatbot, anger_box, st_sid, ...])
send_btn.click(player_say,  inputs=[...],          outputs=[chatbot, anger_box, ...])
textbox.submit(player_say,  inputs=[...],          outputs=[...])
```

這三行就是核心:**「某個元件被觸發 → 呼叫某個 Python 函式(裡面就是後端)→ 回傳值更新指定的元件」**。
- `inputs`:把哪些元件/State 的值,當參數丟給函式。
- `outputs`:函式回傳的值,**按順序**填回哪些元件。

> ⚠️ **outputs 的順序 = return 的順序**,兩邊數量要一致——這是寫 Gradio 最容易出錯的地方。

## 4. 一次「送出」的完整資料流

```
玩家在 textbox 打字、按送出
   │  Gradio 把 inputs 的值傳給 player_say(...)
   ▼
player_say:
   payload = {"player_input": text}
   result = GRAPH.invoke(payload, {thread_id})   ← 進入後端(第 5、6 課的圖)
        └ customer_brain → apply_state → classify_ending → …
   讀 result["ai_reply"]、result["anger"]、result["ended"]
   │  return (新的 chat, 新血條, ...)
   ▼
Gradio 把回傳值按 outputs 順序填回:
   chatbot 顯示新對話、anger_box 更新血條、(結束則 report_col 顯示報告)
```

**前端只負責「呼叫 + 顯示」,遊戲邏輯完全在後端的圖裡。**

---

## 5. 三個關鍵技術點(答辯常問)

1. **thread_id 怎麼讓多回合接起來**
   每按一次「開始挑戰」產生一個 `uuid` 當 thread_id,存進 `gr.State`。之後每次 `invoke` 都帶同一個 thread_id,checkpointer 就自動載回上次的 state(憤怒值、歷史)。換 id = 新遊戲。

2. **第一回合 vs 後續**
   第一回合 `payload = {**init, ...}`(送整包開局 state 初始化);之後只送 `{"player_input": text}`,其餘靠 checkpointer 接續。跟 `run_demo.py` 同邏輯。

3. **後端完全沒改**
   `graph/`、`services/`、`scenarios/` 一行都沒動。app.py 只是「呼叫它 + 顯示結果」。這就是當初把邏輯放後端、跟前端解耦的回報。

## 6. `gr.update` 是什麼?

handler 回傳時常看到 `gr.update(...)`,它的意思是「**只更新這個元件的某些屬性**」:
- `gr.update(interactive=False)`:把輸入框鎖起來(結束時用)。
- `gr.update(visible=True)`:把報告區顯示出來。
- `gr.update()`(空的):這個元件**這次不要變**。

## 🎓 老師可能問

**Q:你的前端怎麼跟後端溝通?**
A:因為 Gradio 也是 Python,前後端在同一程式裡,前端直接 import 後端並呼叫函式(`graph.invoke`、`loader.load`),不需要 HTTP API。事件用 Gradio 的 `.click`/`.submit` 綁定:元件觸發 → 呼叫 handler → 回傳值更新指定元件。

**Q:多個使用者同時玩會不會混在一起?**
A:不會。每場遊戲有自己的 thread_id(存在 gr.State,每個瀏覽器分頁各自一份),checkpointer 以 thread_id 分開保存狀態,所以彼此獨立。

**Q:如果之後前端要換成 React 之類的呢?**
A:那才需要把後端包成 API(例如 FastAPI),前端用 HTTP 呼叫。但後端的圖完全不用改,只是外面多一層 API 殼——這也是把邏輯跟前端解耦的好處。

**Q:為什麼 outputs 要對應 return?**
A:Gradio 把 handler 的回傳值**按順序**填回 outputs 列的元件,所以兩邊數量和順序必須一致,否則畫面會更新到錯的元件。
