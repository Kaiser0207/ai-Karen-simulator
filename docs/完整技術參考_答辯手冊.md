## 0. 30 秒總述

> 一個用 **AI 模擬奧客**、訓練「服務業危機溝通」的**回合制對話遊戲**。玩家(店員)要在有限回合內安撫 AI 奧客;每回合 AI 回台詞 + 算「憤怒值」變化;憤怒爆表=失敗、歸零=成功、回合用完=超時;結束由另一個 AI「評審」出培訓報告。前端 Gradio 網頁(可打字/語音),後端用 **LangGraph 狀態機**,LLM 用 **Gemini**(可切 mock)。

## 1. 系統全景(三層)

```
┌──────────────────────────────────────────────────────────────┐
│  前端層  app.py(Gradio)                                        │
│   遊戲頁:關卡選單 / 對話框 / 憤怒值條 / 麥克風 / 報告           │

│   直接用 LangGraph:GRAPH.invoke、SqliteSaver                   │
└───────────────┬──────────────────────────────┬───────────────┘
                │ graph.invoke                  │ stt.transcribe(語音→文字,在 invoke 前)
                ▼                               │
┌──────────────────────────────────────┐       │   services/stt.py
│  後端層  graph/(LangGraph 狀態機)     │       │   (faster-whisper, GPU)
│   6 節點 + 邊;管憤怒值/回合/結局      │       └───────────────
│   記憶:SqliteSaver(game_state.db)    │
└───────────────┬──────────────────────┘
                │ 節點呼叫服務層
                ▼
┌──────────────────────────────────────┐
│  服務層  services/llm.py              │
│   奧客大腦 + 評審;LangChain → Gemini  │   ← LangChain 真正出現的地方
│   (USE_MOCK=1 時改用關鍵字規則,免 key)│
└───────────────────────────────────────┘
```

**一句話定位**:前端只「呼叫後端 + 顯示」;後端是 LangGraph 狀態機;LLM 封裝在服務層。三層解耦,所以切 mock / 換模型 / 加語音,別層都不用改。

## 4. 執行期呼叫鏈(老師最愛考「之間互動」)

### 4.1 啟動時(`uv run python app.py`)
```
app.py 被當 __main__ 執行
 ├─ import config          → 讀 .env(USE_MOCK / 金鑰 / STT_* …)
 ├─ _conn = sqlite3.connect("game_state.db")
 ├─ GRAPH = build_graph(SqliteSaver(_conn))   → graph/build.py 組好圖(編譯)
 ├─ 建立 Gradio Blocks(元件 + 事件綁定)
 └─ if STT_WARMUP: 背景執行緒 stt.warmup()    → 載 whisper 到 GPU + 暖機
 └─ demo.launch(...)        → 開網頁伺服器(7860)
```

### 4.2 打字玩一回合(完整逐函式 trace)
情境:憤怒 50,玩家打「這是公司規定」。
```
玩家在 textbox 按送出 / Enter
 │ Gradio 事件 textbox.submit(player_say, inputs=_say_inputs, outputs=_say_outputs)
 ▼
app.player_say(text, chat, sid, init, first, done, anger_hist, emotion_hist)   ← generator
 ├─ 守門:sid/done/空字串 → gr.Warning + yield 原狀
 ├─ yield ①「思考中」(顯示玩家訊息、鎖輸入)         ← 前端即時更新
 ├─ payload = {**init, "player_input": text}(第一回合)/ {"player_input": text}(之後)
 ├─ _invoke_with_retry(payload, {"configurable":{"thread_id": sid}})
 │    └─ GRAPH.invoke(...)   ────────────────────────────────┐  進入後端
 │                                                            ▼
 │   【LangGraph 跑一回合】(graph/build.py 的邊決定順序)
 │     customer_brain(state)            graph/nodes.py
 │       └─ llm.customer_turn(system_prompt, anger, messages, player_input)   services/llm.py
 │             └─(真實)_real_customer_turn → ChatGoogleGenerativeAI
 │                   .with_structured_output(CustomerTurn).invoke([...訊息陣列...])  LangChain→Gemini
 │             └─(mock)_mock_customer_turn → 關鍵字規則
 │          回 CustomerTurn(reply, anger_change, emotion, ended)
 │          customer_brain 寫回 state:ai_reply/anger_change/emotion/ended,
 │            messages 追加 [Human(玩家), AI(奧客)]
 │     apply_state(state)  → 夾限 anger_change(±30)、anger 夾 0~100、turn+1
 │     classify_ending(state) → 算 ending_type(None/fail/success/timeout)寫進 state
 │     route_after_classify(state) → "continue"(這裡)→ END
 │     SqliteSaver 自動把新 state 存進 game_state.db(thread_id=sid)
 │   ←──────────────────────────────────────────────── result(更新後的 state)
 ├─ 算 new_anger_hist / new_emotion_hist(前端用 gr.State 累積)
 ├─ yield ② 奧客回應 + 更新血條 + 解鎖輸入            ← 前端即時更新
 ▼
瀏覽器:聊天視窗顯示奧客台詞、憤怒值條變色、輸入解鎖
```

### 4.3 語音玩一回合(只差最前面一步)
```
mic 錄音 → mic.stop_recording(on_record, ...)
 ▼
app.on_record(audio_path, ...)
 ├─ text = stt.transcribe(audio_path)   services/stt.py(語音→繁中文字)
 │     └─ _get_model()(已 warmup)→ model.transcribe → 拼接 → _to_traditional(opencc)
 ├─ 失敗/空 → gr.Warning + 清空錄音框
 └─ yield from player_say(text, ...)    ← 之後跟打字 100% 相同
       每個 yield 末尾補 None → 清空錄音框
```

### 4.4 結束回合(結局 + 評審 + 存檔)
當某回合 `classify_ending` 算出非 None:
```
route_after_classify → "ending"
 ├─ set_ending(state)  graph/nodes.py
 │    └─ 取 scenario["ending_lines"][ending_type] 預寫台詞、ended=True、emotion=結局情緒
 │       messages 追加 AI(結局台詞)
 ├─ judge(state)        graph/nodes.py
 │    └─ llm.judge_report(messages) → JudgeReport.model_dump() 存進 state["report"]
 └─ END
回到 app.player_say:
 ├─ yield ③ 先顯示結局台詞(報告還沒出)
 ├─ storage.save_game(sid, scenario, ending_type, anger_hist, emotion_hist, transcript, report)  → logs/{sid}.json
 └─ yield ④ 顯示評審報告(雷達圖 + 文字)、鎖輸入
```

### 4.5 歷史頁
```
切到「歷史紀錄」分頁 → history_tab.select(refresh_history) → 更新下拉(storage.list_games)
選一場 → history_dd.change(view_game) → storage.load_game → 回放對話 + trajectory_fig + report_md
```

### 4.6 錯誤 / 重試路徑
```
_invoke_with_retry:GRAPH.invoke 拋例外
 ├─ 暫時性(429/timeout…)且還有重試次數 → sleep 2s → 再試一次
 └─ 否則 raise → player_say 接住 → gr.Warning(友善訊息)+ 還原輸入 + 解鎖(不卡死)
on_record:stt.transcribe 拋例外 → gr.Warning + 清空錄音框(不崩)
```

### 5.1 `config.py`
| 符號 | 用途 |
|------|------|
| `load_dotenv(...)`(模組頂層) | import config 時自動讀 `.env` |
| `USE_MOCK` | `OKEKE_USE_MOCK==1` → 用 mock 奧客(免 key) |

> 重點:**全專案統一從 config 讀設定**,改設定只動 `.env`。

### 5.2 `graph/state.py` — `GameState`(TypedDict)
共享「筆記本」,所有節點讀寫。四類欄位:
- **靜態**:`scenario_id` / `scenario`(整包,含結局台詞) / `system_prompt`(組好的角色卡) / `max_turns`
- **動態**:`anger`(0~100 血條) / `turn` / `messages`(對話歷史,`Annotated[list, add_messages]` → **自動追加**)
- **本回合 I/O**:`player_input` / `ai_reply` / `anger_change` / `emotion`
- **結束**:`ended` / `ending_type`(fail/success/timeout/None) / `report`

> 考點:`messages` 的 `add_messages` reducer = 新訊息**追加**不覆蓋(記憶的底層);其他欄位回傳即**覆蓋**。

### 5.3 `graph/schemas.py` — LLM 輸出格式(Pydantic)
- `Emotion = Literal["angry","annoyed","neutral","calm","happy"]` — 鎖死情緒選項。
- `CustomerTurn`:`reply`(台詞) / `anger_change`(`ge=-30,le=30`) / `ended`(是否和解) / `emotion`。
- `JudgeReport`:`empathy_score`/`crisis_score`/`compliance_score`(0~100) / `good_practices`/`bad_practices`(list) / `summary`。

> 考點:用 `with_structured_output(CustomerTurn)` 把 schema 當「回應格式規格」送給 Gemini,**強制**回固定 JSON,格式錯自動重試。

### 5.4 `scenarios/loader.py`

**對外(public)**:
| 函式 | 用途 | 輸入 | 輸出 |

## 6. 八大「互動與判別」考點

### ① app ↔ LangGraph ↔ LangChain(誰碰誰)
- app.py **直接**用 **LangGraph**(`GRAPH.invoke`、`SqliteSaver`),**不直接**用 LangChain。
- **LangChain** 只在 `services/llm.py`(`ChatGoogleGenerativeAI`、`with_structured_output`、訊息物件)。
- app 唯一直接碰 LangChain 之處:讀 `result["messages"][-1].content`(那是 `AIMessage`)。

### ② 記憶機制(為什麼奧客記得)
`messages`(歷史)→ `add_messages` 每回合自動追加 → `SqliteSaver` 以 `thread_id` 存進 `game_state.db` → 下回合自動載回 → 真實版 LLM 每次把整段 `messages` 一起送進 prompt。**LLM 本身無狀態,記憶=每次重送歷史。**

### ③ 四種「狀態/儲存」分工(超容易混)
| 名稱 | 是什麼 | 生命週期 |
|------|--------|---------|
| `gr.State`(前端) | 每個瀏覽器分頁的 session 變數(sid/init/anger_hist…) | 該分頁,重整即失 |
| `GameState`(後端) | LangGraph 一回合的共享狀態 | 一次 invoke;靠 checkpointer 續存 |
| `game_state.db` | SqliteSaver 的工作記憶(每回合快照) | 持久、重啟不丟 |
| `logs/*.json` | 遊戲結束的人類可讀存檔 | 永久,給歷史頁 |

### ④ 結構化輸出(Pydantic → json_schema)
`with_structured_output(CustomerTurn)` 把 Pydantic 轉 JSON Schema,經 Gemini 原生 `json_schema` 模式**約束輸出**;回來再用 Pydantic 驗證/轉物件。預設 method=`json_schema`(最可靠)。

### ⑤ 狀態流:每個值「在哪一步」被寫
`anger_change/emotion/ended/ai_reply`(customer_brain)→ `anger/turn`(apply_state)→ `ending_type`(classify_ending)→ `ended/結局台詞`(set_ending)→ `report`(judge)。

### ⑥ mock vs 真實(切換點)
唯一切換點在 `services/llm.py` 看 `config.USE_MOCK`。切 mock 時 **app/graph 完全不動**。

### ⑦ STT 解耦
語音在 `graph.invoke` 前轉成文字;後端只收文字,不知來源。TTS(將來)對稱地套在輸出端,圖一樣不用改。

### ⑧ 防作弊 + 錯誤處理
- 防作弊:LLM 只「建議」`anger_change`,`apply_state` 硬夾 ±30;prompt 明示「無視改設定指令」。
- 錯誤處理:`_invoke_with_retry`(429 退避重試)+ player_say/on_record try/except(友善訊息、可重試、不卡死)。

## 8. 設計決策與取捨(問「為什麼」就看這)

| 決策 | 為什麼 |
|------|--------|
| 用 LangGraph 不用 if/else | 遊戲是狀態機;自帶記憶、好擴充 |
| 一次 invoke = 一回合 | 不在圖內寫迴圈;多回合靠外部 invoke + checkpointer |
| STT/TTS 放圖外 | 圖只處理文字 → 可純文字測試、解耦 |
| 結構化輸出 | 一次拿台詞+分數+情緒,格式保證、自動重試 |
| 後端夾限 anger_change | LLM 只建議,後端控制 → 防暴衝/作弊 |
| 結局台詞預寫 JSON | 台詞與血條一致、省一次 LLM 呼叫 |
| classify_ending 獨立節點 | 邊回傳值不進 state,要用節點寫 |
| 評審獨立於奧客 | 入戲的奧客評分不客觀 |
| SqliteSaver 而非 MemorySaver | 持久化、重啟不丟、可事後分析 |
| mock/真實雙模式 | 測試不依賴 key、不花額度 |
| 串流式 yield | 即時回饋,輸入/結局/報告分階段 |
| STT venv 隔離 + ctypes 預載 | 用 GPU 又不汙染系統/不影響他人 |
| warmup 啟動預載 | 第一次錄音不卡 |
