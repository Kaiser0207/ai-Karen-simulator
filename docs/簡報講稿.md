## S1 封面 — I WANT TO SPEAK TO THE MANAGER!
**【開口講】**
大家好,我們這組做的是「AI 奧客應對演練」。標題這句「我要找你們經理!」就是每個服務業的人最怕聽到的一句話 —— 我們把它做成一個**可以無限重來、安全練習**怎麼接招的 AI 練習場。

**【技術補充】**
一句話定位:**遊戲化的危機溝通訓練系統**,核心 = LLM 角色扮演 + 語音情緒辨識(SER)。

---

## S2 選題動機
**【開口講】**
服務業天天遇奧客,但**沒有安全的地方練習** —— 找真人演很尷尬、也有代價。我們的想法是:讓 AI 來扮各種刁鑽奧客,你可以無限重來、即時拿到評分。把它做成遊戲:有憤怒值、有結局分支、評審全自動。

**【技術補充】**
動機 → 技術選擇對照:角色扮演 → LLM;即時評分 → 自動評審 LLM;遊戲化 → 狀態機 + 憤怒值數值系統。

---

## S3 全景架構(三結局)
**【開口講】**
整個遊戲有**三種結局**。第一,憤怒值爆表 → 奧客直接砸店,你就輸了。第二,**和解成功** —— 這裡很關鍵:和解是由「**奧客 AI 自己**」在對話當下判定「我被安撫了」,**不是血條歸零**,評審只負責結束後打分。第三,回合用完還沒安撫 → 超時判負。

**【技術補充】**(必背,高頻問)
- 成功 = 奧客大腦 LLM 回傳結構化欄位 `ended=true`,**不是** anger 歸零;
- 失敗 = `anger ≥ 100`;超時 = 回合數耗盡;
- **評審 LLM 不決定勝負**,只在結束後產生評語/分數 → 避免「裁判球員不分」。

---

## S4 技術架構圖
**【開口講】**
系統分兩條線。**主線**:前端(FastAPI + 原生 JS)→ 對話狀態機(LangGraph)→ 分岔成兩個大腦:**奧客大腦**負責演奧客、**評審大腦**負責結束後評分,兩個都是 LLM,可在 Gemini / Groq 間切換。**語音線**:麥克風 → 語音轉文字(faster-whisper)→ 語氣辨識 SER,辨識出的**語氣再回饋給對話狀態機**,影響奧客反應。

**【技術補充】**
- 「奧客大腦」「評審大腦」是**同一套 provider 抽象**下的兩次呼叫(不是兩個不同廠商),用 `CUSTOMER_MODEL` / `JUDGE_MODEL` 環境變數指定;
- LangGraph 是**狀態機**不是單純 chain:節點 = 奧客回應 → 套用狀態 → 分類結局 → 路由 → 評審;
- 語氣是**附加訊號**,跟玩家文字一起進 prompt,不是獨立決策。

---

## S5 核心機制流程
**【開口講】**
一個回合的流程:玩家說話 → 奧客 AI 給反應、同時更新憤怒值 → 後端把憤怒變化**夾在 ±30 以內(防作弊)** → 判定結局:爆表就失敗、奧客說和解就成功、回合用完就超時;**三種結局最後都會進 AI 評審報告**。沒結束就回到玩家繼續說。

**【技術補充】**
- **±30 夾限**是防作弊核心:LLM 可能被玩家用「我送你一百萬」之類話術一次騙到降很多,夾限讓單回合情緒變化合理;
- 評審報告對三種結局都生成(不是只有成功才評)。

---

## S6 亮點1 — 語音 + 情緒識別 ⭐(我的主場)
**【開口講】**
第一個亮點:**我們不只看你說什麼,連你「怎麼說」都算分。** 你錄音進來,先轉成文字,再用我們自己訓練的 SER 模型分成四類語氣 —— 怒、喜、中性、焦慮 —— 把語氣餵給奧客大腦。所以**同一句「不好意思」,你用安撫的語調說,憤怒值降得多;你語氣急促強硬,安撫效果就打折、甚至讓他更生氣**。
而且我們有處理「講很長」的情況:**用詞級時間戳把長句切段、每段分別辨識、再依長度加權**,所以連「一句話前半生氣、後半轉焦慮」這種語氣變化都抓得到。

**【技術補充】**(詞級時間戳 = 真演算法,放心講)
- SER 訓練截斷在 **12 秒**;短句(≤12s)直接整段推論。
- 長句(>12s):`split_long_sentence` 依**詞級時間戳**切段,斷點三層優先序:
  1. **句末標點**(. ? ! 。 ? ! …)—— 區間內最後一個,一定採用;
  2. **子句標點**(, ; : 、 …)—— 最後一個,且該段需 ≥ 25% max_duration(避免切太碎);
  3. **等時平衡** —— 無標點時把剩餘時間均分,挑 `word.end` 最接近目標時刻的詞切。
- 各段分別跑 SER → **依段長加權平均**機率;另回傳 `timeline`(逐段時間區間 + 標籤),可視化語氣隨時間變化。
- 語氣 → 憤怒的作用是**調整係數**(安撫語氣給降怒加成、強硬語氣打折),實際 delta 仍受 ±30 夾限。

## S7 亮點2 — 體驗層設計
**【開口講】**
第二個亮點是體驗。我們做了**班次模式** —— 像上一個班,連續接待好幾位奧客,最後給總結評分。還有**立繪表情系統**:奧客的臉會隨憤怒值變;加上回合倒數製造壓迫感;首頁、戰鬥、勝利各有對應的**寶可夢風背景音樂**。整體做成 RPG 戰鬥畫面的感覺。

**【技術補充】**
- 立繪 = 情緒/憤怒區間 → 對應 sprite;
- 音樂模組有 master volume + duck/crossfade(這部分踩過不少坑,見 S10);
- 班次總結 = 多局結果彙總評分。

## S9 踩雷① — 換關舊回應亂入
**【開口講】**
第一個大坑:**非同步競態**。玩家換關或重開時,上一局還在路上的 AI 回應會「亂入」新回合,畫面就錯亂。解法是**每一局綁定唯一的 myThread ID + 逾時機制**,回來的回應只要對不上當前這局的 ID、或已過期,就**一律丟棄**。

**【技術補充】**
- 機制 = 發請求前快照當前 thread id,`await` 回來後比對,不一致就 return(staleness guard);
- 搭配 AbortController 取消舊請求;典型的**前端非同步 staleness 問題**。

---

## S10 踩雷② — 前端設計(跟 AI 協作)
**【開口講】**
第二個坑其實是**跟 AI 協作開發前端的方法論**。一開始給 AI 模糊需求,它會給你忽對忽錯、甚至幻覺的結果。我們學到的是:**把需求拆成一個個可驗收的小目標、每輪實測、給很精準的回饋、反覆迭代多次**才到位。前端介面、音量、載入這些細節,都是這樣一輪輪磨出來的。

**【技術補充】**(具體例子)
- 音量滑桿拉到 0 跳回 45%(`parseInt(v)||45` 把 0 當 falsy 的 bug);
- 進關卡一直轉圈圈(`preload="auto"` 把 10 個 mp3 同時載、塞爆瀏覽器 6 條連線 → 改 `preload="none"`);
- 都是「小目標逐輪驗收」抓出來的。

## S11 踩雷③ — SER 三難題
**【開口講】**
第三個坑是 SER 落地的三個難題。①瀏覽器錄音是 webm,SER 讀不了 → 我們用 faster-whisper 統一解碼成 PCM。②主專案跟 SER 的 PyTorch 版本衝突 → 拆成**獨立微服務、各跑各的 venv**,用 HTTP 溝通。③模型原本只用英文資料訓練,中文準確率掉下來 → 目前靠**多語預訓練編碼器的跨語言遷移 + prompt 補語境**頂著,這也是我們未來要做雙語重訓的原因。

**【技術補充】**
- 微服務溝通 = 主程式用 stdlib `urllib` 打 `/predict_pcm`,音訊用 base64 PCM 傳;
- 「跨語言遷移」= 音訊用 wav2vec2-XLS-R-300M、文字用 XLM-RoBERTa-large,**這兩個本身是多語預訓練**,即使只用英文情緒資料微調,也能部分泛化到中文;
- ✅ **真實數字(雙語重訓已完成 2026-06-11)**:同一份中文 test,**舊英文模型 macro-F1 0.46 → 新雙語模型 0.57(+24.5%)**,準確率 0.52→0.64,**四類全升**(Angry/Happy/Neutral/Anxious)。這就是「跨語言遷移頂著 → 真的補中文資料重訓」前後對比。

# 📋 附錄 A — 老師可能問的問題 + 標準答案

## 架構層
1. **為什麼用 LangGraph,不直接呼叫 LLM?**
   → 遊戲是**有狀態的多回合流程**:要管憤怒值、回合數、判三種結局、決定要不要叫評審。LangGraph 把這些做成**節點 + 條件路由**,流程清楚、好除錯、好擴充,不是一坨 if-else。

2. **和解到底誰判定?評審還是奧客?**(高頻)
   → **奧客大腦 LLM** 在對話當下回傳 `ended=true` 代表「我被說服了」。**評審不參與勝負**,只在結束後評分。裁判跟球員分開。

3. **憤怒值是 LLM 自己給的嗎?會不會亂給?**
   → LLM 提議變化量,後端**夾在 ±30**。防玩家話術一句騙到歸零,也防 LLM 暴衝。

4. **兩個大腦是兩個不同模型嗎?**
   → 是**同一套 provider 抽象的兩次呼叫**,各有自己的 system prompt 與 `CUSTOMER_MODEL`/`JUDGE_MODEL` 設定,可獨立指定模型。

## 模型層(SER — 廖寬仁主場)
5. **SER 模型架構是什麼?**
   → 基於 **CRAB 多模態情緒辨識**:音訊編碼器 + 文字編碼器,各過 Unimodal Block(FC→LayerNorm→BiGRU),再做 **Cross-Modal 交叉注意力 + Attention Pooling**,拼接後過分類層,訓練時有 **MPCL 對比學習**輔助。把原論文 WavLM 換成 **wav2vec2-XLS-R-300M**、RoBERTa 換成 **XLM-RoBERTa-large**(多語版,支援中文)。

6. **用什麼資料、怎麼訓練?**
   → **MSP-Podcast**,8 類映射成 4 類(怒/喜/中性/焦慮)。**LoRA** 微調(rank 16/alpha 32),batch 16、約 8 epochs、AMP + gradient checkpointing 省顯存、早停。

7. **準確率多少?用什麼指標?**
   → **WAR(整體準確率)、UAR(各類平均召回)、macro-F1**。**情緒類別不平衡,看 UAR / macro-F1 比看 accuracy 公平。**(具體數字待雙語重訓補)

8. **中文準嗎?**(高頻,誠實答 — 現在有數字了)
   → 一開始只用**英文**情緒資料微調,中文靠多語編碼器遷移、會掉。所以做了**雙語重訓**:MSP(英)+ EmotionTalk(中)train **2.5:1** + LoRA + 50:50 語言平衡取樣,並把**模型選擇改成以中文 dev 為準**。結果**中文 test macro-F1 從 0.46 → 0.57(+24.5%),四類全升**。代價是英文略降(0.63→0.54),但遊戲只用中文,值得。

9. **長句怎麼處理?**(可主動秀)
   → 詞級時間戳切段(句末標點 > 子句標點 ≥25% > 等時平衡),各段 SER 後依段長加權,輸出逐段 timeline。

10. **為什麼不用現成情緒 API?**
   → 現成多半固定類別/語言、要錢、改不動權重;我們要**自訂 4 類 + 中文 + 可微調**,所以自己訓。

## 工程層
11. **STT 延遲多少?即時嗎?** → faster-whisper,單句約一兩秒內,體感接近即時;模型啟動時暖機,首次錄音不卡。

12. **為什麼 SER 拆微服務?** → 主專案跟 SER 的 **PyTorch 版本衝突**;拆開各自 venv,用 HTTP(`/predict_pcm`,base64 PCM)溝通,互不干擾,GPU 進程也隔離。

13. **Gemini 跟 Groq 怎麼選?** → Gemini 品質好但免費額度容易 **429**;Groq 快又穩。provider 抽象兩邊可切,平常 Groq 測、正式 demo 可切 Gemini。

14. **換關卡競態怎麼解?** → 每局唯一 **myThread ID** + 快照比對 + AbortController,過期/錯局回應一律丟棄。

15. **錄音存哪?隱私?** → 錄音在記憶體解碼成 PCM 送 SER,不長存。

16. **成本?** → 每回合約 1 次奧客 LLM 呼叫,結束時 1 次評審呼叫;免費額度足夠 demo。

# 📋 附錄 B — 系統技術細節速查

**LangGraph 節點流**
`customer_brain`(奧客回應 + 提議憤怒 delta)→ `apply_state`(夾 ±30、更新回合)→ `classify_ending`(判 ended / anger≥100 / 回合用盡)→ `route`(條件路由)→ `set_ending` → `judge`(評審報告)。

**勝負真值表**
- 成功 = `CustomerTurn.ended == true`
- 失敗 = `anger ≥ 100`
- 超時 = 回合耗盡
- 三者都觸發 `judge`。

**SER 推論鏈**
webm →(`faster_whisper.decode_audio`,底層 PyAV/ffmpeg)→ PCM(np.float32 16k mono)→ STT 出文字 + 詞級時間戳 →(`train_norm_stat` 波形正規化)→ XLS-R 音訊塔 + XLM-R 文字塔 → CRAB 融合(`MultiModalEmotionClassifierDeep`)→ `final_ser.pt` 4 類 softmax → `[Angry, Happy, Neutral, Anxious]`。

**長語句分段加權演算法**(`split_long_sentence` / `predict_chunked`)
- 觸發:語句 > 12 秒(SER 訓練截斷)。
- 斷點優先序:① 句末標點(一定採用)→ ② 子句標點(段長 ≥ 25% max)→ ③ 等時平衡。
- 各段 SER → 依段長加權平均;輸出 `timeline`(逐段標籤 + 機率)。

**SER 服務介面**
獨立 venv(torch 2.2+cu121、peft、transformers)起 uvicorn;主程式 `urllib` POST `/predict_pcm`,body 帶 base64 PCM + text + words,回 `{label, confidence, probs, chunks, timeline?}`。

**雙語重訓配方**(✅ 已完成,完整細節見**附錄 C**)
XLS-R + XLM-R;LoRA r16/a32/do0.1;**batch 24 × accum 2(有效 48)**;epochs 10/早停5(實際 epoch9 早停,best epoch4);lr 2e-4 / encoder 1e-4;contrastive 2.0;`--language_balanced`;**train EN:ZH 2.50:1**(MSP 9633/類=38532 : EmotionTalk 全收 15413);**dev 只留中文選 best**;AMP + grad-ckpt。→ **中文 test macro-F1 0.46→0.57(+24.5%)**。

**前端競態防護**
發請求前快照 myThread id → `await` 回來比對 → 不一致丟棄(staleness guard)+ AbortController 取消舊請求。

**音訊 / 音樂工程要點**
- webm/opus 統一用 faster-whisper 解碼成 16k PCM(免裝額外 ffmpeg 綁定);
- 音樂:master volume + duck/crossfade;`preload="none"` 避免連線飽和;音量 0 修正(Number.isNaN 判斷)。

# 📋 附錄 C — SER 模型完整技術細節(答老師專用)

> 被問「這情緒模型怎麼做的」時照這份講:架構 → 資料 → 超參數 → 訓練 → 結果 → 取捨。

## C-1 任務 & 為什麼雙模態
- 辨識的是**玩家(店員)講話的「語氣」**(不是奧客);4 類 **Angry / Happy / Neutral / Anxious**。
- **雙模態**:同時看「聲音(音訊)+逐字稿(文字)」→ 比只看文字準(同一句話,語調不同情緒就不同)。

## C-2 架構(CRAB 多模態 `MultiModalEmotionClassifierDeep`)
| 區塊 | 內容 |
|---|---|
| **音訊編碼器** | `wav2vec2-XLS-R-300M`(多語自監督語音,輸出 1024 維)+ LoRA(q_proj/v_proj) |
| **文字編碼器** | `XLM-RoBERTa-large`(多語文字,1024 維)+ LoRA(query/value) |
| **單模態塊** | 各自 FC → LayerNorm → **BiGRU**(抓時序) |
| **跨模態塊** | **Cross-Attention(音訊↔文字互看)+ 殘差 + Attention Pooling**(各模態壓成一向量) |
| **分類塊** | 兩模態向量拼接 → LayerNorm → FC → ReLU → Dropout → FC → 4 類 |
| **對比學習** | **MPCL 多層對比監督**(同情緒拉近、不同情緒推遠),`contrastive_weight 2.0` |

- **為什麼換編碼器**:原 CRAB 論文用 WavLM + RoBERTa(英文)→ 我們換**多語版** XLS-R + XLM-R 才能吃中文。
- **可訓練參數只 22.58M**:base 編碼器**凍結**,只訓 LoRA(音訊 1.57M + 文字 1.57M)+ 融合/分類頭。

## C-3 資料集
| 語言 | 來源 | 4 類映射 |
|---|---|---|
| 英 EN | **MSP-Podcast**(8 情緒) | Angry=Angry+Disgust+Contempt / Happy=Happy+Surprise / Neutral=Neutral / Anxious=Sad+Fear |
| 中 ZH | **EmotionTalk**(7 情緒) | Angry=anger+disgust / Happy=happy+surprise / Neutral=neutral / Anxious=sad+fear |

- 中文共 **19,250 筆**(Angry 4638 / Happy 3468 / Neutral 9378 / Anxious 1766)。
- **train 比例 EN:ZH = 2.50:1**(MSP 每類砍到 9633=38,532 : EmotionTalk 全收 15,413);`--language_balanced` 取樣器再讓**每批 50:50**。
- 中文文字用 **opencc s2twp 轉繁體**,對齊遊戲 STT 輸出(訓練/部署文字一致)。
- **切分**:train 53,945 / **dev 1,908(只留中文 → 用來選 best)** / test 7,929(英+中,事後分語言評估)。

## C-4 訓練超參數(完整)
| 項目 | 值 |
|---|---|
| 微調法 | **LoRA**,rank **16** / alpha **32** / dropout **0.1** |
| LoRA 目標層 | 音訊 q_proj/v_proj、文字 query/value |
| batch / 累積 | batch **24** × accumulation **2** = 有效 batch **48** |
| 學習率 | 分類頭/LoRA **2e-4**、編碼器 **1e-4** |
| epochs | 10(`early_stop_patience 5` → 實際 **epoch 9 早停**,best @ **epoch 4**) |
| 對比 / 裁切 | contrastive_weight **2.0**、grad_clip **1.0** |
| 模型維度 | fusion_hidden **512**、text_max_len **128**、音訊截斷 **12 秒** |
| 省顯存 | **AMP(fp16 混合精度)+ gradient checkpointing** |
| 類別權重 | 反頻率:Angry 1.01 / Happy 1.08 / Neutral 0.78 / Anxious 1.23 |
| 暖啟 | **無**(純 HF base + 新 LoRA) |
| 硬體 / 耗時 | RTX 3090 24GB、VRAM **~17GB**、**~32 分/epoch**、共 **~6 小時** |

## C-5 評估指標 & 模型選擇
- **WAR**=整體準確率;**UAR**=各類召回平均;**macro-F1**=各類 F1 平均。
- **類別不平衡 → 看 UAR / macro-F1 比看 accuracy 公平**(accuracy 會被多數類灌水)。
- **模型選擇**:以**中文 dev 的 macro-F1** 早停 → 確保挑到「中文最好」的 epoch(關鍵設計)。

## C-6 結果(分語言評估,vs 舊英文模型,同一份中文 test)
| 中文 test | 舊(純英文) | **新(雙語)** | |
|---|---|---|---|
| 準確率 WAR | 0.524 | **0.636** | +11 pts |
| **macro-F1** | **0.459** | **0.571** | **+24.5%** |
| Angry F1 | 0.62 | 0.66 | |
| Happy F1 | 0.35 | 0.50 | |
| Neutral F1 | 0.58 | 0.71 | |
| Anxious F1 | 0.28 | 0.43 | |

- 中文 dev best macro-F1 **0.6287**(epoch 4)。
- **弱點**:**Anxious 最弱**(中文訓練樣本最少 1369;低喚醒情緒**聲學上與 Neutral 近似** → 互混)。
- **英文 test 0.54**(舊英文模型本來 ~0.63)→ 刻意中文導向的**取捨**,遊戲只跑中文不影響。

## C-7 老師可能追問(SER 專屬)
- **為什麼 LoRA 不全量微調?** → 省顯存、訓得快、小資料防過擬合;只動 2.5% 參數就達標。
- **為什麼有效 batch 才 48?** → 對比學習要看**實體 batch** 的正負例;24GB 下 batch 24 是 VRAM 與對比效果的甜蜜點(batch 32 逼近 21GB 太緊)。
- **為什麼用中文 dev 選 best?** → 目標是中文準;用合併 dev(76% 英文)會挑到「英文最好」的 epoch,選錯。
- **為什麼英文會降?** → 模型被導向中文的取捨,且遊戲只用中文,不在意英文。
- **怎麼證明中文真的變準?** → 同一份中文 test、同樣指標,舊 0.46 → 新 0.57,**四類全升**(不是只看單一數字)。
- **長句怎麼辦?** → 詞級時間戳切段、各段辨識、依段長加權(見附錄 B)。
