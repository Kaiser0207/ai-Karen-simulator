# 語音情緒辨識模型(SER)— CRAB / MSP 4 類

> 給「AI 奧客應對演練」用的語音情緒辨識:辨識**玩家(店員)講話時的語氣情緒**,
> 之後硬映射成遊戲訊號(爆氣/冷靜回應等)。模型訓練於 2026-06-09 完成。

---

## 1. 用途定位

- 語音輸入流程目前是 **錄音 → faster-whisper(STT)→ 文字** 進遊戲。
- SER 是要再加一條:**同一段錄音 → CRAB → 情緒**,讓系統知道玩家「語氣」如何
  (例如玩家明明在安撫卻語帶不耐),做為回饋或影響奧客反應。
- 辨識對象是**玩家本人**(非畫面上的奧客)。

## 2. 模型架構(CRAB,雙模態跨模態對比)

CRAB = 雙塔編碼 + 跨模態融合 + 多正例對比學習,專為情緒辨識設計。

```
   音檔 ──► 音訊編碼器  XLS-R-300M (wav2vec2)  ─┐
                                                ├─► 跨模態 Transformer 融合 ─► SER 分類頭 ─► 4 類
   文字 ──► 文字編碼器  XLM-RoBERTa-large       ─┘                │
                                                                  └─► Multi-Positive Contrastive Loss(MPCL)
```

| 元件 | 用的模型 / 機制 |
|---|---|
| 音訊編碼器 | `facebook/wav2vec2-xls-r-300m`(跨語言自監督,3 億參數) |
| 文字編碼器 | `FacebookAI/xlm-roberta-large`(多語,中文友善) |
| 融合 | 跨模態 Transformer(audio↔text 互相 attend) |
| 損失 | 分類 CE + **多正例對比損失 MPCL**(同情緒互相靠近、跨情緒推遠) |

**對比損失重點**:MPCL 的正負樣本池 = **當前 mini-batch**,所以 batch 太小會失效;
本次 batch=16(每類 4 筆)是可用下限。

## 3. 訓練設定(LoRA 微調)

| 項目 | 值 | 備註 |
|---|---|---|
| 微調方式 | **LoRA**(r=16, α=32, dropout 0.1) | 只動 adapter + SER 頭,省 VRAM、避免全參數過擬合 |
| 暖啟動 | `experiments/strategyA_fullft` | 沿用既有全參數權重起跑 |
| 學習率 | head `1e-4` / encoder `1e-5` | **關鍵**:預設 1e-3 會在 epoch 1 崩潰 |
| 對比權重 | `contrastive_weight=2.0` | MPCL 啟用 |
| batch / 累積 | 16 / 1 | dev/test 評估用 ×4=64 |
| epochs | 8(early-stop patience 5) | 實際跑滿 8 |
| 省記憶體 | AMP 混精度 + gradient checkpointing + 懶載音檔 + `num_workers=0` | **全程 GPU 單跑、未 OOM** |
| 硬體 | RTX 3090 24GB | 訓練峰值 ~24GB(訓練時關閉遊戲 server 讓出 whisper 2.2GB) |

### 資料:MSP-Podcast 8 類 → 4 類

| 遊戲 4 類 | 由 MSP 哪幾類合併 |
|---|---|
| **Angry** | Angry + Disgust + Contempt |
| **Happy** | Happy + Surprise |
| **Neutral** | Neutral |
| **Anxious** | Sad + Fear |

- 平衡子採樣:**train 10k/類 = 40k**、dev/test 各 **1.5k/類 = 6k**。
- 建構腳本:`scripts/build_okeke_msp_4class.py` → `data/okeke_msp_4class.csv`。

## 4. 結果(準確度)

**最佳:dev macroF1 = 0.6265(epoch 7);TEST macroF1 = 0.6297 / UAR 0.6323 / loss 0.912**
(test 略高於 dev → 無過擬合、泛化良好。4 類隨機基準 = 0.25。)

### 逐 epoch dev macroF1
```
e0 .577  e1 .544  e2 .615  e3 .596  e4 .592  e5 .6215  e6 .6245  e7 .6265(best)
```
- e3–4 短暫下滑是**雜訊**(dev loss 同步下降),非過擬合。
- **e5→e7 一路爬升、最後一個 epoch 仍在進步 → epoch 數其實太少**(見下「改善方向」)。

### TEST 各類 F1
| 類別 | Precision | Recall | F1 | 對遊戲意義 |
|---|---|---|---|---|
| 😡 Angry | 0.637 | **0.725** | 0.679 | recall 高 → **爆氣幾乎不漏**(對遊戲最重要,有利) |
| 😄 Happy | 0.666 | 0.705 | **0.685** | 最佳 |
| 😐 Neutral | 0.530 | 0.637 | 0.579 | 收容所類,天生難 |
| 😟 Anxious | **0.769** | 0.461 | 0.577 | recall 低,常被當 Neutral |

### 混淆結構
- 弱點是 **Anxious ↔ Neutral 互混**:兩者皆低喚醒、語調平,聲學近似,接近**資料本質天花板**(連人工標註都常分歧),非訓練沒練好。
- 遊戲核心(爆氣 / 開心)偵測可靠,弱點落在對遊戲影響最小的低喚醒端。

## 5. 改善方向(ROI 由高到低)

1. **加 epochs(12~15)**:最後 epoch 還在升,最省事、最可能破 0.63+。
2. **全量資料 + 加權取樣**:目前只用 40k(丟掉 MSP 約 13 萬筆大半),+1~3pt 可期。
3. **LoRA rank 32 + cosine LR**:小幅、便宜。
4. **校準 Angry 閾值**:對遊戲體感的提升 > 拚整體 macroF1。
5. (結構性)contrastive batch 被 24GB VRAM 卡在 16,要更大需砍音檔長度/凍底層,風險高。
