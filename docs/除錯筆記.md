# 除錯筆記 — Kaiser0207

> 我在後續開發踩到的問題與解法,與朋友的 [`開發錯誤紀錄.md`](開發錯誤紀錄.md) 區隔。

## Gradio 6.0:`theme` / `css` 要在 `launch()` 傳,不是 `Blocks()`
- **症狀**:`gr.Blocks(theme=..., css=...)` 完全沒生效,只噴一行 UserWarning。
- **原因**:Gradio 6.0 把 `theme`/`css` 從 `Blocks` 建構子搬到 `launch()`。放 `Blocks()` 會被忽略
  (連朋友原本的 `css=CUSTOM_CSS` 在 Gradio 6 上也一直默默失效)。
- **解法**:`demo.launch(..., theme=THEME, css=CSS)`。

## `pkill -f "python app.py"` 會把自己殺掉
- **症狀**:指令異常結束(exit 143 / 144)。
- **原因**:`pkill -f` 比對整條命令列,連「正在執行 pkill 的那行 bash」本身(字串內含 `python app.py`)也被一起殺。
- **解法**:改用 PID:`kill $(ss -ltnp | grep ':<PORT>' | grep -oP 'pid=\K[0-9]+' | head -1)`。

## 前景等待被環境中止(exit 144)
- **症狀**:`sleep`、`curl --retry-delay` 在前景被中止。
- **解法**:用 `curl --retry N --retry-connrefused`(伺服器一啟動就返回,不會空等),或改零等待檢查。

## 從本機(Windows)連不到遠端 server
- **症狀**:瀏覽器開 `127.0.0.1:<PORT>` 顯示 ERR_CONNECTION_REFUSED;app 其實跑在遠端 fcu-server3。
- 進一步:從本機 `ssh` 遠端的 port 22 timeout(校園防火牆對外擋)。
- **解法**:用 **VS Code 的 PORTS 面板** Forward 該埠,再開 `http://127.0.0.1:<PORT>`(VS Code Remote-SSH 自帶轉發)。

## `git push` 回 403(明明讀得到)
- **症狀**:已存憑證能讀(`GET /user`、讀 public repo 都 OK),一 `push` 就 403「Permission denied」。
- **原因**:已存的是**唯讀 / 未涵蓋此 repo 的 fine-grained token**。
- **解法**:`gh auth login`(瀏覽器 OAuth 取得有寫入權的 token),push 時用 gh 的憑證 helper:
  `git -c credential.helper= -c credential.helper='!gh auth git-credential' push ...`。

## commit 作者不是我的 GitHub 帳號
- **症狀**:GitHub 顯示作者是別的帳號(用錯 email),我沒被算成 contributor。
- **解法**:`git config user.email "<id>+<login>@users.noreply.github.com"`;舊 commit 用
  `git filter-branch --env-filter ... -- --all` 改寫作者,再 `git push --force`。

## 結局判定被「血條歸零」搶判 success(設計 bug)
- **症狀**:玩家只一直道歉把顧客哄到怒值 0,還沒提出任何解決方案,卻立刻判定「和解成功」。
- **原因**:`classify_ending` 寫成 `anger<=0 or ended → success`,血條低只代表顧客冷靜,不等於問題解決。
- **解法**:移除 `anger<=0` 分支,和解只由 LLM `CustomerTurn.ended` 決定。
  結局優先級明文化:**fail(爆表)> success(ended)> timeout(回合用盡)**。

## 伺服器重啟 / TTL 後,進行中的對局「工作階段不存在」
- **症狀**:`SESSIONS` 是純記憶體 dict,uvicorn 重啟即清空,玩家對話到一半就 404。
- **解法**:graph state 本來就由 `SqliteSaver` 以 thread_id 持久化 → `_get_session` 記憶體找不到時改查
  `GRAPH.get_state(cfg).values`,有 `scenario` 就以 `first=False` 還原續玩。並把 anger/emotion 軌跡改以
  graph state 為準(`emotion_history` 加進 `GameState`,reducer 累加),不再依賴記憶體累加。

## SQLite 單連線多執行緒
- **症狀**:`check_same_thread=False` 讓多執行緒共用同一連線,同時用同一 cursor 並不安全,可能 "database is locked" 或資料錯亂。
- **解法**:連線加 `timeout=30` + `PRAGMA journal_mode=WAL`;再用一把 `_DB_LOCK` 把 `GRAPH.invoke / get_state` 序列化
  (訓練工具併發極低,序列化最簡單安全;要真併發再換 Postgres / 連線池)。

## 真實 LLM 回傳不符 schema → 整場 503
- **症狀**:`with_structured_output` 遇 LLM 隨機性回傳格式不符,直接拋 ValidationError,web 回 503,玩家卡死。
- **解法**:`_invoke_structured` 同 prompt 退避重試 3 次;仍失敗時走後備——奧客回中性台詞(遊戲續行)、
  評審退回 mock 關鍵字報告(結束一定有結算),不再整場無回應。

## 對話「答非所問、罐頭句」→ 其實是跑到 mock 大腦
- **症狀**:奧客一直回「我等很久了欸,你倒是說句話啊」「聽起來你好像有在聽」等,跟上下文對不上。
- **原因**:server 啟動時帶了 `OKEKE_USE_MOCK=1`(免金鑰測 UI 用),mock 大腦是**關鍵字+字數挑罐頭句**,不懂語意。
  且 `load_dotenv` **預設不覆蓋**已存在的環境變數 → 啟動時的 `OKEKE_USE_MOCK=1` 會蓋過 `.env` 的 `=0`。
- **解法**:要真實語意對話,啟動**不要**帶 `OKEKE_USE_MOCK`(讓它讀 `.env` 的 `OKEKE_USE_MOCK=0` + `LLM_PROVIDER=gemini` + 金鑰)。
  純測 UI/plumbing 才用 `OKEKE_USE_MOCK=1`(省額度)。

## Whisper(medium)中文常漏標點符號
- **症狀**:用 medium 模型轉繁中,輸出幾乎沒有逗號/句號/問號。
- **原因**:小模型對標點較不穩;且沒給任何風格引導時傾向不輸出標點。
- **解法**:`transcribe` 傳 `initial_prompt`= 一句**本身含標點的中文**(`config.STT_PROMPT`)→ Whisper 會延續該風格把標點補出來;
  再加 `vad_filter=True` 去靜音、減少幻聽。**最有效是換大模型**(large-v3 標點明顯更好;RTX 3090 跑得很輕鬆)。

## 自訂網頁前端(REST)沒有麥克風 → 用 MediaRecorder + /api/stt
- **背景**:語音原本只在 Gradio 版(`gr.Audio` 元件)。自訂前端是純 HTML/JS,要自己錄音上傳。
- **解法**:前端 `MediaRecorder` 錄成 webm/opus blob → `FormData` POST `/api/stt`;後端 `UploadFile` 暫存 →
  `faster-whisper`(PyAV 可直接解 webm/opus)→ 回文字。transcribe 同步且吃 GPU → 用 `run_in_threadpool` 不擋事件迴圈。
- **注意**:`FormData` 上傳**不要**自己設 `Content-Type`(讓瀏覽器帶 multipart boundary);FastAPI 檔案上傳需 `python-multipart`(已裝)。

## AKARU 選關卡縮放一直「卡卡的 / 突然放大縮小」
- **症狀**:用「手風琴」依距離改 `width`,放大縮小頓挫;改純平移又做不到「3 細條 + 焦點長到 60%」。
- **原因**:① 直接改 panel 寬會讓裡面的視覺/文字**跟著重排(reflow)**,每幀重算文字排版 → 卡。
  ② 純平移是固定寬,沒有縮放,無法同時呈現休息態三細條與焦點 60%。
- **解法**:**裁切式 slice**——外框只動 `flex-basis` 並 `overflow:hidden`,內層固定 `60vw`(=焦點寬)。
  變寬只是「露出更多同一張內容」,內層尺寸不變、不重排 → 縮放滑順。焦點用浮點 `curF`(滾輪累加 ÷ STEP,
  再 lerp)驅動,`fracFor(索引−curF)` 連續給寬度;大名等外框長到 >40% 才淡入。

## 加 calm_resistance 後 test_apply_state 兩個案例 KeyError: 'scenario'
- **症狀**:`apply_state` 加入怒氣衰減係數後,`pytest` 兩個既有測試掛 `KeyError: 'scenario'`。
- **原因**:測試 `_state()` 只塞 anger/anger_change/turn/emotion,**沒有 `scenario` 鍵**;
  我寫成 `state["scenario"].get(...)`,負向 delta 分支直接踩空。
- **解法**:改 `(state.get("scenario") or {}).get("calm_resistance", 1.0)` —— 缺 scenario 視為係數 1.0。
  教訓:節點讀「關卡靜態欄位」時一律走 `.get` 防呆,單元測試常只給最小 state。

## 網頁黑畫面、「載入中…」轉不停(localhost vs 127.0.0.1)
- **症狀**:瀏覽器開 `localhost:8000` 一直黑畫面、分頁標題卡「載入中…」,但 server 完全正常。
- **關鍵診斷**:server log **看不到瀏覽器那筆請求**(只有我 curl 的 127.0.0.1)→ 請求根本沒送達。
  `ss -tlnp` 顯示 server 只聽 `0.0.0.0:8000`(**純 IPv4**),`curl [::1]:8000` → HTTP 000(不通)。
- **原因**:Windows 的 Chrome 把 `localhost` **優先解析成 `::1`(IPv6)**,而 server / VS Code 連線埠轉發只在 IPv4 → 連到 `::1` 沒人接 → 永遠卡連線。
- **解法**:網址改用 **`127.0.0.1:8000`(強制 IPv4)** 即解。或在 VS Code「連接埠」面板重新轉發 8000。
  教訓:server restart 後黑畫面,先分清「server 掛了」還是「連線沒到」——看 server log 有沒有那筆請求最快。`localhost`≠`127.0.0.1`(IPv6/IPv4 之別)。

## 選關 carousel:標語休息態先藏 + 三關填滿右半
- **需求**:起始只露藍/粉/綠三條、各加寬佔右半(標題 0.52 不動);標語「低怒氣・好安撫」拉開才顯示。
- **做法**:① `DIFF_STYLE.rest` 0.16/0.11/0.075 → **0.20/0.16/0.12**(三關和 0.48 + 標題 0.52 = 1.0,「敬請期待」自然溢出被 `overflow:hidden` 裁掉,捲到底才現)。
  ② `.s-genre` 包進 `.rev`(`<span class="rev s-genre"><span>…</span></span>`)→ 自動進 `revCache` 階梯揭露;**藥丸樣式從外層移到內層 `span`**(否則休息態會露出空藥丸)。
- **注意**:rest 必須 < 0.40(`a=smooth((frac-0.40)/0.20)` 在 rest<0.40 時 =0 → 休息態 foot/標語都藏)。0.20 安全。
- 靜態檔免重啟(server 即時讀盤),瀏覽器 Ctrl+R 即見。

## 換關後舊回應「亂入」新對局 + 「思考中」永遠卡住(2026-06-10)
- **症狀**:某客人 `/api/say` 回得很慢(卡「⌛ 思考中」),我按結束關卡換到別關,**舊關的奧客回應突然冒出來貼進新關**(連怒氣/回合數都是舊的)。
- **原因**:`send()` 的 `await` 沒有「對局身分」概念 —— 離開後舊請求一 resolve,`.then` 照樣 `addMessage`/`updateMeter` 寫進**目前**畫面。
- **解法**:送出前記 `const myThread = STATE.thread`,await 回來後 `if (STATE.thread !== myThread) return;` 整個丟棄(success/catch 都檔)。`startCustomer` 也用 `myShift` 守衛。結束關卡把 `STATE.thread` 設 null → 在途回應必被守衛擋掉。
- **卡死**:`/api/say` 90s、`/api/start` 45s `AbortController` 逾時 → 不再永遠轉,改友善提示 + 還原輸入。

## 重複「你」泡泡 + 倒數無限自動重送(2026-06-10)
- **症狀**:撞 Groq 額度(429)時,同一句「你」泡泡疊三四個,而且自己一直重送。
- **原因**:① 送失敗時「你」泡泡已先加上去、沒收回。② 我為了「失敗後還能重打」在 catch 裡 `startTurnTimer()` → 倒數到 → `onTimerExpire` 看到輸入框有字 → 自動 `send()` → 又 429 → 再疊一個 → 無限。
- **解法**:失敗時 `userNode.remove()` 收回泡泡 + **不**自動重啟倒數(伺服器端那回合也沒推進,移除泡泡才一致)。

## 好客人(customer_kind=nice)每場必超時(2026-06-10)
- **症狀**:暖心常客、林小姐這種好客人,怎麼服務都「超時・無效溝通」,從不「和解」。
- **原因**:`customer_kind` 欄位**載入時根本沒用到**;好客人套到通用「奧客」prompt,而 `ended=true` 的定義是「提出完美方案解客訴」—— 好客人沒客訴 → 永遠不 `ended` → 撐到回合用盡 = 超時。
- **解法**:`loader._build_system_prompt` 依 `customer_kind=="nice"` 附加覆蓋:被親切招待/給好建議就 `ended=success`、不硬拖、不重複問。

## 報告卷軸一直戳出圓角邊(改結構才根治)(2026-06-10)
- **歷程**:無邊距 → 戳出;加 `margin:32px` → 又覺得太空、滑塊貼頂底卡。
- **根因**:卷軸是卡片自身的,`border-radius:26px` 在四角會裁切/露出卷軸,純調 margin 兩難。
- **解法**:外層包一個 `.report-frame`(給圓角 + 陰影 + `overflow:hidden` + `transform:translateZ(0)` GPU 合成),**內層 `.report-card` 才捲動** → 卷軸被外框圓角乾淨裁掉、物理上不可能戳出;滑塊再留 16px 不貼頂底。

## 背景音樂:自動播放被擋 / 音量滑桿沒反應 / 載入卡頓(2026-06-10)
- **自動播放**:瀏覽器禁止無使用者手勢自動出聲 → 首頁音樂不會自己響。解:`pointerdown/keydown/wheel` 第一次觸發才啟動目前畫面音樂(`{once:true}`)。
- **音量滑桿拖了沒感覺**:滑桿在「設定」裡,而**一開設定背景樂就被壓低**,加上 `setVolume` 原本「壓低時不套用」→ 在設定裡只聽到壓低後的音量。解:`setVolume` **即時預覽真實音量**(忽略壓低);壓低改成**主音量×比例**(不是固定值)→ 整組音量一起縮放,Healed 跟背景固定差距。
- **一開始卡一下**:原始 **WAV 125MB**,`preload=auto` 一進站就狂抓 → 卡首屏。解:**ffmpeg 轉 MP3(12MB)**、`music/*.wav` gitignore、大廳曲 + 全立繪改 `requestIdleCallback` 在空閒才預載。

## SER 接遊戲:webm 解碼 / 跨 venv / 多模態 的坑(2026-06-10)
- **webm 解不了**:瀏覽器 MediaRecorder 給 webm/opus,SER venv 的 `librosa`(libsndfile)讀不了 webm。解:**遊戲端用 `faster_whisper.decode_audio` 解碼一次**(底層 PyAV/ffmpeg)成 16k 波形,轉 int16 PCM base64 走 JSON 丟微服務(`/predict_pcm`)→ 微服務免再解 webm、免 multipart。
- **跨 venv 依賴衝突**:CRAB 在自己的 `.venv`(torch 2.2+cu121),遊戲 venv 沒那些。解:**獨立微服務**,遊戲只用 stdlib `urllib` HTTP 呼叫,best-effort、沒開就略過。
- **多模態**:模型要 audio+text 兩路;推論要把 STT 逐字稿一起餵。且模型是**英文 MSP 訓練**,中文屬 OOD(音訊靠 XLS-R 跨語言遷移、文字分支較弱)。
- **舊 `api/inference.py` 不能用**:那是 3 類 WavLM 版、載全量 `final_ssl/final_text`;4 類是 LoRA → 必須 `PeftModel.from_pretrained(adapter)` + `final_ser.pt`。

## 音量滑桿拉到 0 卻跳回 45%(2026-06-10)
- **症狀**:背景音樂音量滑桿拖到最底(0),顯示數值與實際音量瞬間跳回 45%。
- **原因**:`parseInt(v, 10) || 45` —— JS 把 **0 視為 falsy**,`0 || 45` = 45;`loadMusicVol` / `saveMusicVol` 兩處都中。
- **解法**:改 `const n = parseInt(...); Number.isNaN(n) ? 45 : n`,0 是合法值不再被吃。**教訓**:欄位「0 是合法值」時,別用 `|| 預設`,要用 `Number.isNaN` / `== null` 判斷。

## 設定裡音量「偶發調不動」(2026-06-10)
- **症狀**:開設定拖音量滑桿,有時拖了沒反應、音量不動。
- **原因**:`setVolume` 用 100ms 淡入做預覽,這個淡入會被「開/關設定的壓低淡入(250ms)」或「大廳換軌淡入」插隊清掉、落空。
- **解法**:`setVolume` 改**即時直接設 `cur.volume` + 先 `clearInterval` 掉進行中的淡入**,不再跟其他淡入搶 → 拖一下立刻變、不再失靈。

## 進關卡後立繪/憤怒條/開場白全空白、載入非常久(2026-06-10)
- **症狀**:遠端 server 經 VS Code 埠轉發開站,進關卡後三張卡片(立繪/憤怒條/對話)全空白、等很久才出現,像一直轉圈。
- **關鍵診斷**:在 server 本機 `curl /api/start` 只要 **0.009s** → 後端不慢;慢的是瀏覽器端載入。
- **原因**:進關卡 `MUSIC.preloadBattle()` 一次抓 **6 個戰鬥/勝利 mp3**(`<audio preload="auto">`),**HTTP/1.1 同網域上限 6 條連線全被大檔佔滿** → `/api/start` 與立繪圖片排在後面等;慢隧道下更久 → `startCustomer` 渲染遲遲不出來。
- **解法**:`<audio>` 改 **`preload="none"`**(play() 時才串流),不在進站/進關搶頻寬 → UI 與 API 立刻通;音樂改要播才載(慢網路下首播略延遲、可接受)。**教訓**:慢網路/隧道下,媒體預載(`preload="auto"` × 多檔)會悄悄把關鍵 API/圖片餓死在連線佇列裡。
